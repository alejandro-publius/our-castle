# PayPal AI Hackathon — source summary

Sources: the owner's November 3 materials, plus the official [PayPal AI Hackathon rules](https://paypalaihackathon.devpost.com/rules), [resources](https://paypalaihackathon.devpost.com/resources) and linked sponsor briefs checked November 5, 2026. This summary is not a replacement for the official rules.

**Deadline: November 12, 2026 at 12:00 p.m. PST** (both pastes agree; the Devpost page showed "9 days to deadline" on November 3).

## Requirements (Devpost page)

Build or update an application that integrates the PayPal developer platform using the free sandbox, together with an AI tool, model or platform of your choice. The project should:

- meaningfully integrate at least one PayPal technology, API, SDK, product or developer capability ("PayPal integration is central");
- meaningfully incorporate AI into the experience or functionality;
- demonstrate a working prototype or proof of concept;
- be documented well enough for judges to understand and evaluate it;
- comply with the official rules. Existing projects are allowed if meaningful progress happens during the event. Sponsor AI tools are optional.

## Submission

- Text description of features and functionality.
- Functional demo: complete setup and run instructions in the repository, or a hosted demo URL. Mockups, static prototypes or non-functional demos do not qualify.
- Tools: identify the AI model/service used and explain how it is used. (Our Castle: Anthropic Claude `claude-opus-5-5` through the Messages API, as the runtime milestone planner with server-side validation and as the read-only house steward that checks PayPal through the Agent Toolkit. A coding assistant's involvement in building the project is not the runtime AI feature.)
- Public code repository on GitHub, GitLab or Bitbucket with all source, assets and instructions, open source, with a visible license file.
- Demo video under three minutes, on YouTube and publicly visible, showing the project working on its target device, with no third-party trademarks or copyrighted music/material used without permission.

## Judging criteria

Technological implementation (thorough, skillful, non-trivial use of PayPal and AI); design (a complete, coherent product, not just a proof of concept); potential impact (a credible, specific problem and audience, addressed by what is demonstrated); innovation; presentation (end-to-end demo, clear problem/audience/why).

## Implementation route chosen

- **PayPal, server:** PayPal's official Server SDK (`@paypal/paypal-server-sdk`, generated by APIMatic) for Orders v2 create/capture/get and Payments v2 refunds, fixed to the sandbox environment, as in PayPal's Node integration guide (October 8, 2026). Webhooks v1 signature verification and v6 client tokens use a minimal REST client against `api-m.sandbox.paypal.com`.
- **PayPal, browser:** JavaScript SDK v6 from `www.sandbox.paypal.com/web-sdk/v6/core`, initialized with `clientId` and a `createOrder` promise resolving to `{ orderId }`, matching that guide. A client-token fallback is kept.
- **PayPal + AI:** PayPal's Agent Toolkit gives the AI house steward two read-only tools (`get_order`, `list_transactions`). Money-moving tools are never enabled, and the steward cannot create, capture or refund. This is a deliberately human-in-the-loop take on agentic commerce.
- **AI:** Anthropic `claude-opus-5-5` for the milestone planner (structured output, validated by the server) and the steward (tool use, with server-side reconciliation and dollar-figure checks).
- **Sponsor tools:**
  - APIMatic: the generated Server SDK plus eight installed and used SDK-specific context skills for Codex.
  - AG Grid Community and AG Studio: records, a themed custom milestone widget, and Agent Framework lifecycle for the existing steward through a custom server runner.
  - Channel3: real products/prices in Market Town, creating an explicitly confirmed goal draft.
  - Postman: a runnable collection for the example and sandbox flows.

  Not used: Render hosting/Workflows (example Blueprint only), Zapier, Elastic, Kernel, Astropods, Bryntum.
- **Considered and left out on purpose:** PayPal Pay Later messaging. Promoting credit inside a savings game would work against the product's purpose.
